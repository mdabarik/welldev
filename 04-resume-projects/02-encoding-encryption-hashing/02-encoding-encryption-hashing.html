Encoding, Encryption ও Hashing

তিনটাই data-কে অন্য রূপে বদলায়, কিন্তু উদ্দেশ্য সম্পূর্ণ আলাদা — format বদলানো, গোপন রাখা, আর verify করা। যেকোনো ছবিতে click করলে বড় করে দেখা যাবে।

01

Encoding

Format / representation বদলানো। কোনো key নেই, security নেই।
02

Encryption

Key দিয়ে data গোপন করা। সঠিক key থাকলে আবার ফেরত আনা যায়।
03

Hashing

One-way fixed-length fingerprint। Password storage-এর জন্য।
1

Encoding

নির্দিষ্ট নিয়ম (agreed rule) দিয়ে data-এর format বদলানো

কীভাবে কাজ করে

  • Original data → Encoder (rule) → Encoded output → Decoder → Original।
  • Rule জানা থাকলে যে কেউ decode করতে পারে।

উদাহরণ

  • "A" → ASCII 65 → 01000001
  • "Man" → Base64 TWFu
  • ASCII, UTF-8, UTF-16, Base64, URL Encoding।

মনে রাখো

  • Encoding ≠ Encryption — data লুকানোর জন্য না।
  • উদ্দেশ্য: data transfer, storage compatibility, binary-কে text হিসেবে পাঠানো।
2

Encryption

Plaintext → Ciphertext, শুধু সঠিক key দিয়ে ফেরত আনা যায়

Symmetric

  • Encrypt ও decrypt — একই key।
  • উদাহরণ: AES।
  • দ্রুত, বড় data-র জন্য ভালো; কিন্তু key নিরাপদে share করা কঠিন।

Asymmetric

  • Public key দিয়ে encrypt, Private key দিয়ে decrypt।
  • উদাহরণ: RSA, ECC।
  • ধীর, কিন্তু key exchange ও digital signature-এ দরকারি (HTTPS)।

কেন ব্যবহার হয়

  • Data confidentiality।
  • Secure communication (HTTPS / TLS)।
  • File ও database সুরক্ষিত রাখা, secure messaging।
3

Hashing ও Password Security

One-way function — password + salt → hash

Sign up ও Login

  • Sign up: password + random salt → hash → DB-তে algorithm, salt, cost, hash রাখা।
  • Login: DB থেকে salt + settings নিয়ে আবার hash করে compare।
  • Hash মিললে login success, না মিললে fail।

Salt ও Cost Factor

  • Salt: প্রতিটা password-এর জন্য unique random value — rainbow table আটকায়।
  • Cost factor: hashing ইচ্ছা করে slow করে — brute-force কঠিন হয়।
  • bcrypt cost 10–14, Argon2 m, t, p।

Good Practices

  • bcrypt / Argon2 / scrypt ব্যবহার করো।
  • শুধু SHA-256 password-এর জন্য যথেষ্ট না (খুব fast)।
  • কখনো plain password store করবে না।
