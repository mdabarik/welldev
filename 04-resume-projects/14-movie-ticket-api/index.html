API DESIGN

একটা API design করতে
কী কী লাগে?

Movie ticket booking বানাতে বানাতে ধাপে ধাপে দেখি। শেষে React থেকে সত্যিকারের request পাঠিয়ে উত্তর দেখবে।

শুরু করো ↓ Request পাঠিয়ে দেখো পুরো app ↗

প্রথমে: পাঁচটা method, client আর server কোড

React (fetch) থেকে request পাঠাই, Express-এ সেটা ধরি। প্রতিটা method-এ কী পাঠাতে হয় আর server-এ কোথা থেকে কী পাওয়া যায়, পাশাপাশি দেখো।

মেথডURLবডি লাগে?সার্ভারে কী পাওয়া যায়সফল হলে স্ট্যাটাস
POST/usersহ্যাঁreq.body201
GET/users/5 বা /users?page=2নাreq.params, req.query200
PUT/users/5হ্যাঁ (পুরো অবজেক্ট)req.params, req.body200
PATCH/users/5হ্যাঁ (শুধু পরিবর্তন)req.params, req.body200
DELETE/users/5নাreq.params204 বা 200
সবগুলোতেই Authorization header একইভাবে যাচ্ছে, কারণ প্রতিটা request-এ পরিচয় দিতে হয়। আর যেখানে বডি আছে (POST, PUT, PATCH), শুধু সেখানেই Content-Type: application/json দরকার।

প্রতি route-এ আলাদা করে token না দেখে: middleware

বাস্তব project-এ প্রতিটা route-এ আলাদা করে token যাচাই না করে একটা middleware বানিয়ে একবারেই লাগিয়ে দেওয়া হয়। এই project-এও তাই করা আছে।







ধাপে ধাপে API design


কোড লেখার আগে এই ১০টা প্রশ্নের উত্তর ঠিক করলেই API-র নকশা হয়ে যায়।



1

  
কোন কোন জিনিস নিয়ে কাজ?

  
আগে ঠিক করো system-এ কী কী "জিনিস" (resource) আছে। API এই জিনিসগুলোর চারপাশেই গড়া হয়।

  
🎬 movie🕒 showtime🎟 booking👤 user

  
সম্পর্ক: একটা movie-র অনেক showtime, একটা showtime-এ অনেক booking (প্রতিটায় কয়েকটা seat)।





2

  
প্রতিটার একটা URL (endpoint)

  
নিয়ম: URL-এ থাকবে জিনিসের নাম (বহুবচন), কাজের নাম নয়। কাজ বোঝাবে method।

  

    
✗ ভুল/getMovies · /createBooking · /deleteMovie?id=4

    
✓ ঠিক/movies · /movies/4 · /movies/4/showtimes · /bookings

  





3

  
কাজ বোঝাতে HTTP method

  
একই URL, কিন্তু method বদলালে কাজ বদলায়।

  

    
GETপড়া: GET /movies/4

    
POSTনতুন তৈরি: POST /bookings

    
PUTপুরোটা বদলানো: PUT /movies/4 (সব field পাঠাতে হয়)

    
PATCHআংশিক বদল: PATCH /movies/4 { "rating": 9.1 }

    
DELETEমোছা: DELETE /bookings/7

  





4

  
Request-এ কী কী পাঠানো যায়

  
চারটা জায়গা, প্রতিটার আলাদা কাজ।

  

    
pathকোন জিনিস: /movies/4

    
queryছাঁকনি, পাতা: ?search=inc&page=2

    
headerপরিচয় আর ধরন: Authorization, Content-Type

    
bodyনতুন বা বদলের data (JSON): { "seats": ["A1"] }

  





5

  
Response-এর একটা নির্দিষ্ট আকার

  
সফল আর ব্যর্থ দুই ক্ষেত্রেই সবসময় একই ছাঁচ, যাতে client সহজে পড়তে পারে।

  

    
// সফল
{ "data": { "id": 7, "status": "pending" } }

// তালিকা
{ "data": [ … ],
  "meta": { "page": 1, "total": 3 } }

    
// ব্যর্থ
{ "error": {
    "code": "SEAT_TAKEN",
    "message": "এই seat আগেই booked: A2",
    "details": { "seats": ["A2"] } } }

  





6

  
Status code দিয়ে ফল জানানো

  
প্রথম অঙ্ক দেখলেই বোঝা যায় কেমন খবর: 2 সফল, 4 তোমার ভুল, 5 server-এর ভুল।

  

    
200 OKসফল (GET, PUT, PATCH)

    
201 Createdনতুন তৈরি (POST)

    
204 No Contentমোছা হয়েছে, body নেই

    
400 Bad Requestinput ভুল

    
401 Unauthorizedtoken নেই বা ভুল

    
403 Forbiddenঅনুমতি নেই

    
404 Not Foundজিনিসটা নেই

    
409 Conflictসংঘর্ষ (seat আগেই নেওয়া)

    
500 Server Errorserver-এ গোলমাল

  





7

  
কে ডাকছে? (Authentication)

  
একবার login করে token নাও। এরপর প্রতিটা request-এর header-এ সেটা দেখাও। Server শুধু token যাচাই করে।

  
POST /api/auth/login   { "email": "…", "password": "…" }   →  { "token": "eyJhbGci…" }

GET  /api/bookings
Authorization: Bearer eyJhbGci…

  
401 = তুমি কে জানি না (token নেই/ভুল)। 403 = জানি, কিন্তু এই কাজ তোমার নয় (user হয়ে admin-এর কাজ)।





8

  
ব্যবসার নিয়ম আর validation

  
URL আর method ঠিক থাকলেও API-র আসল কাজ নিয়মগুলো মানানো। Server-এই এগুলো ঠিক করবে, client-এর ওপর ভরসা করে নয়।

  

    
input যাচাইভুল seat, খালি title → 400, কোন field ভুল তা সহ

    
seat সংঘর্ষদুজন একই seat চাইলে প্রথমজন পায়, দ্বিতীয়জন 409

    
মালিকানানিজের booking ছাড়া দেখা যাবে না → 403

    
সময়ের নিয়মpending seat ১০ মিনিট আটকে থাকে, পরে ছাড়া পায় (410)

  





9

  
বড় হলে: pagination, filter, version

  
তালিকা বড় হলে একবারে সব না পাঠিয়ে ভাগ করে দাও। আর পরে নিয়ম বদলালে পুরনো client যেন না ভাঙে।

  

    
pagination/movies?page=2&limit=10 → meta.totalPages

    
filter/movies?genre=Sci-Fi&search=inc

    
version/api/v1/movies, বদল এলে /api/v2

  





10

  
Document আর test

  
Endpoint-এর তালিকা লিখে রাখো (method, URL, auth, সফল হলে কোন code)। আর প্রতিটা endpoint একবার করে চালিয়ে status code মিলিয়ে দেখো। এই project-এ ৫৩টা check আছে (npm test)।






React থেকে request পাঠানো


React-এ আলাদা কিছু নেই। সাধারণ fetch, শুধু header আর body ঠিকমতো বসাতে হয়।



const headers = { Accept: 'application/json', 'Content-Type': 'application/json' };
const token = localStorage.getItem('token');
if (token) headers.Authorization = `Bearer ${token}`;      // ← Bearer token

const res  = await fetch('/api/bookings', {
  method: 'POST',
  headers,
  body: JSON.stringify({ showtimeId: 1, seats: ['A1', 'A2'] }),
});
const data = res.status === 204 ? null : await res.json(); // 204-এ body থাকে না
if (!res.ok) throw new Error(data.error.message);          // 400, 401, 409 …



নিচে এই fetch-ই চলছে, একটা নকল server-এর বিরুদ্ধে। যেকোনো request বানিয়ে পাঠাও।
