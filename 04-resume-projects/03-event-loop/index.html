Event Loop — একটা thread, অনেক কাজ

JavaScript-এ একসাথে একটাই কাজ চলে। তাহলে setTimeout, fetch আর Promise একসাথে সামলায় কীভাবে? উত্তর: call stack, কিছু queue, আর একটা loop।

1মূল কথা

Call Stack — যে কাজ এখন চলছে। একবারে একটাই। Stack ব্যস্ত থাকলে বাকি সবাইকে অপেক্ষা করতে হয়।

Queue — অপেক্ষার লাইন। সময় বা I/O শেষ হলে callback এখানে এসে দাঁড়ায়। দুই রকম: Microtask (Promise) আর Task (setTimeout, event)।

Event Loop — একটা অবিরাম loop। Stack খালি হলে queue থেকে পরের কাজ তুলে stack-এ দেয়। এটা ছাড়া callback কখনো চলত না।

while (true) {
  runMicrotasks();            // stack খালি → আগে সব microtask
  const task = taskQueue.next();
  if (task) run(task);        // তারপর একটা task
}

2Browser / JavaScript

Microtask আগে, Task পরে
নিয়ম: Script নিজেই একটা task। প্রতিটা task শেষ হলে stack খালি হয়, আর তখন event loop পুরো Microtask queue খালি করে, তারপর পরের একটা Task নেয়। তাই Promise.then সবসময় setTimeout(…, 0)-এর আগে চলে।

3Node.js

একই ধারণা, কিন্তু loop-এ আছে phase

Node-এ event loop চালায় libuv। Loop প্রতি ঘূর্ণনে ধাপে ধাপে phase পার হয়: timers → pending → poll → check → close। ফাইল, crypto-র মতো ভারী কাজ যায় thread pool-এ; নেটওয়ার্কের কাজ OS নিজে সামলায়। এই উদাহরণে I/O callback-এর ভেতরে চারটা জিনিস register হয় — ক্রমটা সবসময় একই।

নিয়ম: প্রতিটা callback-এর পর (এবং phase বদলের আগে) Node আগে process.nextTick queue খালি করে, তারপর Promise microtask। তাই nextTick → promise সবসময় আগে। এরপর poll শেষে check phase-এ setImmediate চলে, আর timer চলে পরের ঘূর্ণনের timers phase-এ।

Main script থেকে ডাকলে?

console.log('A');
setTimeout(() => console.log('timeout'), 0);
setImmediate(() => console.log('immediate'));
process.nextTick(() => console.log('nextTick'));
Promise.resolve().then(() => console.log('promise'));
console.log('D');
$ node main.js     (১২ বার চালিয়ে — Node v20.12.1)
9 বার:  A D nextTick promise timeout immediate
3 বার:  A D nextTick promise immediate timeout

A, D, nextTick, promise সবসময় এই ক্রমে। কিন্তু main script থেকে timeout আর immediate-এর ক্রম নিশ্চিত না — loop শুরু হওয়ার সময় 1 ms পার হয়েছে কিনা তার উপর নির্ভর করে। I/O callback-এর ভেতরে immediate সবসময় আগে (উপরের animation)।
