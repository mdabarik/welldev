Who owns what?

PCB, TCB, register আর cache কোথায়?

PCB

PCB থাকে kernel memory-তে

Process ID, address-space/page-table reference, open files, credentials ও process-level accounting রাখে। Exact layout OS-ভেদে আলাদা।

PCB hardware chip নয়—OS kernel-এর protected data structure।
TCB

TCB-ও kernel memory-তে

Thread ID, state, priority, stack pointer এবং saved CPU context রাখে। অনেক OS-এ PCB/TCB আলাদা object না হয়ে task structure-এ মিলেও থাকতে পারে।

Context switch-এ registers core থেকে TCB/kernel stack-এ save হয়।
REG

চলার সময় register core-এ

PC, SP ও general-purpose registers CPU core-এর hardware। Thread switch হলে পুরনো value memory-তে save, নতুন thread-এর value restore হয়।

Thread register-এর মালিক নয়; thread-এর register state-টি OS সংরক্ষণ করে।
L1

L1/L2 সাধারণত core-local

L1 instruction/data cache এবং সাধারণত L2 প্রতিটি core-এর কাছে private। Thread core বদলালে warm cache হারাতে পারে।

Cache thread-এর নয়। Layout CPU architecture অনুযায়ী বদলাতে পারে।
L3

L3 সাধারণত package-shared

এক CPU package-এর বহু core last-level cache share করতে পারে। Cache coherence একই memory line-এর view মিলিয়ে রাখে।

“L1/L2 private, L3 shared” common model—universal rule নয়।
MMU

MMU/TLB CPU hardware

MMU virtual address translate করে। TLB সাম্প্রতিক page translation cache করে; miss হলে RAM-এর page-table walk লাগে।

Page table RAM-এ; তার root/reference PCB-এর address-space info-তে থাকে।
Address translation · one memory access

Application শুধু virtual address দেখে। CPU-এর load/store instruction-এর address MMU নিচের পথে translate করে।

Concurrency ≠ Parallelism

দ্রুত পালা বদল, নাকি সত্যিই একই সময়ে?

Single-core-এ scheduler এত দ্রুত context switch করে যে সব app একসাথে চলছে মনে হয়। Multi-core-এ একাধিক thread একই মুহূর্তে execute করতে পারে।

নোট: Hyper-Threading এক physical core-কে একাধিক logical CPU হিসেবে expose করতে পারে; এটি extra physical core-এর সমান নয়।
