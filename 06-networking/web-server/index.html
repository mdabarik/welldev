Nginx বনাম Apache: একসাথে ১২টা request

    
প্রতিটা request-এ কাজ তিন ভাগে: একটু CPU কাজ (0.1s), তারপর app/database-এর জন্য অপেক্ষা (1s), তারপর আবার একটু CPU কাজ (0.1s)। Apache (prefork)-এ প্রতিটা request পুরো সময় একটা process আটকে রাখে — অপেক্ষার সময়ও। Nginx-এর worker অপেক্ষা করে বসে থাকে না; request-টা epoll-এ রেখে পরেরটা ধরে।

Nginx কী করে?
সামনে দাঁড়িয়ে থাকা দারোয়ান: TLS খোলে, static file নিজেই দেয়, বাকিটা proxy_pass দিয়ে app-এ পাঠায়, একাধিক app থাকলে load balance করে, gzip আর access log লেখে।

      
Apache কোথায় আলাদা?
পুরোনো, module-ভিত্তিক (.htaccess, mod_php)। prefork / worker MPM-এ প্রতি connection-এ process বা thread লাগে, তাই অনেক ধীর connection একসাথে এলে memory বেশি লাগে। নতুন event MPM অনেকটা Nginx-এর মতো।

      
App server কেন আলাদা?
Node, Spring, Django-তে আপনার business logic চলে। Nginx এটা সামনে থেকে আড়াল করে — app crash করলে Nginx অন্তত 502 দেখাতে পারে, আর একাধিক app instance-এ ভাগ করে দিতে পারে।

      
Keep-alive আর cache
প্রথম request-এ DNS, TCP, TLS-এ সময় যায়। একই connection খোলা থাকে (keep-alive), তাই পরের request এগুলো ছাড়াই যায়। Redis cache থাকলে database পর্যন্তই যেতে হয় না।

    

  


  

    

      
TCP connection setup কীভাবে হয়?

      
Browser বা Nginx নিজের হাতে TCP segment বানায় না। তারা socket-এর মাধ্যমে operating system-কে বলে; দুই computer-এর OS networking stack তখন connection setup করে। এই flow-তেই TCP stack, socket ও OSI layer কোথায় কাজ করে দেখুন।

01
TCP stack
Operating system-এর ভেতরের networking software। সাধারণ Linux, Windows বা macOS-এ এটি মূলত kernel-এর মধ্যে থাকে—CPU-তে code হিসেবে চলে, RAM-এ connection-এর state রাখে।

      
02
Socket
Application আর OS networking-এর মাঝের দরজা। Application-এর কাছে একটি handle/file descriptor থাকে; kernel-এর কাছে থাকে IP, port, buffer ও connection state-সহ socket object।

      
03
Client বনাম server
Technology একই TCP। যে side connection শুরু করে সে client; যে side port-এ অপেক্ষা করে সে server। একই computer প্রয়োজনে দুই ভূমিকাতেই থাকতে পারে।

TCP কী দিচ্ছে?

Identity—সঠিক server কি না, confidentiality—data গোপন, এবং integrity—data বদলেছে কি না।

GET /..., headers ও response TLS records-এর মধ্যে encrypted থাকে; TLS records আবার TCP data হিসেবে যায়।

    


    
কোথায় চলে? সাধারণ setup-এ client-side TLS browser-এর TLS library-তে এবং server-side TLS Nginx/OpenSSL-এর মতো user-space software-এ চলে। নিচে OS kernel-এর TCP/IP stack একই সময়ে ACK, retransmission, ordering, flow control ও congestion control চালিয়ে যায়। Diagram-টি TLS 1.3-এর একটি সহজ full-handshake view; resumed connection আরও ছোট হতে পারে।
