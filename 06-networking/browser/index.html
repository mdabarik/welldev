    ৩<head>-এর <link> কীভাবে কাজ করে
    
      
    Browser HTML উপর থেকে নিচে পড়ে আর পড়তে পড়তে DOM নামের গাছ বানায় (একে বলে parsing)। <link rel="stylesheet"> পেলে কী হয়, আর CSS কেন head-এ রাখা হয়:
    
    
    
      
    ১. Download শুরু, কিন্তু parsing থামে না
    
        
    <link rel="stylesheet" href="style.css">
    
        
    Browser সাথে সাথে style.css চেয়ে পাঠায় আর HTML পড়া চালিয়ে যায়। DOM তৈরি হতে থাকে।
    
      
    ২. কিন্তু CSS না আসা পর্যন্ত কিছু আঁকে না
    
        
    CSS ছাড়া আঁকলে প্রথমে style-ছাড়া এলোমেলো page দেখা যেত, তারপর হঠাৎ বদলে যেত (একে বলে FOUC — flash of unstyled content)। তাই browser CSSOM তৈরি না হওয়া পর্যন্ত screen আঁকে না। একে বলে render-blocking।
    
      
    ৩. পরের সাধারণ script-কেও আটকায়
    
        
    <link rel="stylesheet" href="style.css">
<script>getComputedStyle(el).color</script>
    
        
    Script element-এর রং বা মাপ জানতে চাইতে পারে, তাই CSS শেষ না হলে তার পরের সাধারণ (বা inline) script চলে না। async script এই অপেক্ষা করে না।
    
      
    ৪. তাই CSS থাকে <head>-এ
    
        
    যত আগে browser CSS-এর খোঁজ পায়, তত আগে download শুরু, তত আগে প্রথম paint। Body-র মাঝখানে <link> রাখলে দেরিতে খোঁজ পায়, আর তার উপরের অংশ style ছাড়া দেখা যেতে পারে।
    
    
    
    
    <head>-এ আরও যেসব <link> কাজে লাগে
    
      
    <link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>   <!-- আগেভাগে DNS + TCP + TLS সেরে রাখো -->
<link rel="preload" as="image" href="hero.webp">                 <!-- এই ফাইলটা জরুরি, এখনই নামাও -->
<link rel="stylesheet" href="print.css" media="print">       <!-- শুধু print-এ লাগে → render আটকায় না -->
<link rel="icon" href="favicon.png">                         <!-- tab-এর ছোট আইকন -->
    
      
    এই page-এর head-এও Google Fonts-এর জন্য preconnect আছে।
    
    
    
      
    ছবি (<img>) parsing থামায় না
    
        
    • Download শুরু হয়, parser পরের লাইনে চলে যায়; ছবি নামলে নিজের জায়গায় বসে।
      • 
          
    • width আর height দিন — না দিলে ছবি আসার পর নিচের লেখা লাফিয়ে সরে (layout shift)।
      • 
          
    • স্ক্রিনের নিচের ছবিতে loading="lazy"; কিন্তু প্রথম স্ক্রিনের বড় ছবিতে না।
      • 
          
    • ছবি <head>-এ থাকে না — head-এ শুধু preload বা favicon-এর <link>।
    
      
    Preload scanner — লুকানো সাহায্যকারী
    
        
    Parser কোনো script-এর জন্য থেমে থাকলেও browser-এর একটা ছোট অংশ সামনের HTML-এ চোখ বুলিয়ে <img>, <link>, <script src> খুঁজে আগেভাগে download শুরু করে দেয়।
    
        
    তাই blocking script থাকলেও ছবি সাধারণত দেরিতে নামে না — দেরি হয় দেখানোয়। উপরের timeline-এর ১ নম্বর mode-এ দেখুন, parser থেমে থাকার সময়েই photo.webp নামা শুরু হয়েছে।
    
    
    
  
    

  
  
    
    
    ৪<script>: সাধারণ, async, defer আর body-এর শেষে
    
      
    সাধারণ <script> পেলে parser পুরো থেমে যায় — কারণ script document.write() দিয়ে HTML-এই কিছু লিখে দিতে পারে, তাই browser আগে দেখে নেয় script কী করে।
    
    
    
      
    লেখাDownload-এর সময় parsing থামে?কখন চলেক্রম ঠিক থাকে?পুরো DOM পায়?DOMContentLoaded আটকায়?
    
      
        
    <script src> (head)হ্যাঁসাথে সাথে (আগের CSS শেষ হলে)হ্যাঁনা — নিচের element নেইহ্যাঁ
    
        
    asyncনাdownload শেষ হলেই — parsing-এর মাঝখানেওনা — যেটা আগে নামেকখনো হ্যাঁ, কখনো নানা
    
        
    deferনাপুরো HTML পড়া শেষে, DOMContentLoaded-এর ঠিক আগেহ্যাঁ, লেখার ক্রমেহ্যাঁঅপেক্ষা করায়, কিন্তু parsing থামায় না
    
        
    type="module"নাdefer-এর মতোইহ্যাঁহ্যাঁdefer-এর মতো
    
        
    <script src> (body-এর শেষে)হ্যাঁ, কিন্তু একদম শেষেparser ওখানে পৌঁছালেহ্যাঁহ্যাঁ (উপরের সব)হ্যাঁ
    
        
    inline <script>…</script>download নেই, সাথে সাথে চলেparser যেখানে পায় সেখানেইহ্যাঁশুধু উপরেরগুলোখুব অল্প
    
          
    
    

    
    
      
    async দিলে DOM-এর কাজ ভাঙতে পারে — হ্যাঁ
    
        
    async script কখন চলবে সেটা ঠিক করে download কখন শেষ হলো — HTML কতটুকু পড়া হয়েছে তা না।
    
        
    • File দ্রুত এলে (cache থেকে): button তখনো parse হয়নি → querySelector দেয় null → error। (timeline-এর mode ২)
      • 
          
    • File ধীরে এলে: ততক্ষণে সব পড়া শেষ → কাজ করে। (mode ৩)
      • 
          
    • সবচেয়ে বিপদের দিক — কখনো চলে, কখনো চলে না। আপনার দ্রুত internet-এ bug দেখাই যায় না, অন্যের কাছে ভাঙে।
      • 
          
    • দুটো async-এ ক্রম নেই: ছোট app.js আগে নামলে gsap is not defined।
    
      
    সমাধান
    
        
    ১. সবচেয়ে সহজ: async-এর বদলে defer।
    
        
    ২. async রাখতেই হলে script-এর ভেতরে DOM-এর জন্য অপেক্ষা করুন:
    
        
    function start() {
  document.querySelector("#buyBtn").addEventListener("click", buy);
}
if (document.readyState === "loading") {
  document.addEventListener("DOMContentLoaded", start); // এখনো পড়ছে → শেষ হলে চালাও
} else {
  start();                                             // আগেই শেষ → এখনই চালাও
}
    
        
    শুধু DOMContentLoaded listener যথেষ্ট না — async script ওই event-এর পরেও চলতে পারে (mode ৩), তখন listener আর কখনো চলবে না।
    
      
    <body>-এর শেষে script রাখলে কী সমস্যা
    
        
    • দেরিতে খোঁজ পায়: parser পুরো body পড়ার পর script দেখে, তখনই download শুরু। head-এ defer থাকলে HTML পড়ার শুরুতেই নামা শুরু হয়। (mode ৪ আর ৫ তুলনা করুন)
      • 
          
    • এখনো parser-blocking: একদম শেষে হলেও parser থামে, তাই DOMContentLoaded দেরি হয়।
      • 
          
    • দেখা যায়, কিন্তু কাজ করে না: screen-এ button চলে আসে, কিন্তু script না আসা পর্যন্ত click করলে কিছু হয় না।
      • 
          
    • একাধিক script একটার পর একটা নামে-চলে, প্রতিটায় আবার থামে।
    
        
    সুবিধাও আছে: উপরের সব DOM তৈরি, আর page আগে দেখা যায়। defer আসার আগে এটাই চলত; এখন head-এ defer প্রায় সবসময় ভালো।
    
      
    দুটো আলাদা "শেষ"
    
        
    • DOMContentLoaded — HTML পড়া শেষ, defer script-ও চলা শেষ। ছবির জন্য অপেক্ষা করে না। DOM-এর কাজ শুরু করার সঠিক সময়।
      • 
          
    • load — সব শেষ: ছবি, CSS, iframe সব নামা। শুধু তখন দরকার, যখন ছবির আসল মাপ লাগে।
    
        
    নিজে দেখতে: Chrome-এ F12 → Network → reload। নিচে নীল দাগ DOMContentLoaded, লাল দাগ load।
    
    
    
  
    

  
  
    
    
    ৫কখন কোনটা ব্যবহার করবেন
    
      
    নিজেকে প্রশ্নগুলো করুন — বাঁ দিকে প্রশ্ন, ডান দিকে কী লিখবেন।
    
    
    
      
    নিজের app-এর JavaScript, DOM ছোঁয় (button, form, menu)
    →
    <script defer src> head-এparallel download, পুরো DOM পায়, ক্রম ঠিক থাকে
    
      
    একাধিক file, একটা আরেকটার উপর নির্ভর করে (gsap → app.js)
    →
    সবগুলো defer, ঠিক ক্রমেasync দিলে ক্রম ভেঙে যায়
    
      
    আধুনিক import / export code
    →
    <script type="module">নিজে থেকেই defer-এর মতো
    
      
    একদম স্বাধীন third-party — analytics, বিজ্ঞাপন, error tracking
    →
    <script async>DOM ছোঁয় না, কারো উপর নির্ভর করে না, যত আগে চলে তত ভালো
    
      
    খুব ছোট code, যা প্রথম paint-এর আগেই চলা দরকার (যেমন dark theme বসানো)
    →
    inline <script> head-এdownload নেই; এই page-এর theme এভাবেই বসে, তাই রং ঝলকায় না
    
      
    পুরোনো CMS / template, head-এ কিছু বদলানো যায় না
    →
    <body>-এর শেষেকাজ করে, তবে দেরিতে download শুরু হয়
    
      
    CSS
    →
    <link rel="stylesheet"> head-এশুধু print-এর CSS হলে media="print"
    
      
    প্রথম স্ক্রিনের বড় ছবি
    →
    <img width height> + preloadনিচের ছবিতে loading="lazy"
    
    
    
    
    এক লাইনে: DOM ছোঁয় বা অন্য script-এর উপর নির্ভর করে → defer। একদম স্বাধীন, DOM ছোঁয় না → async। CSS → head-এ link। ছবি → width/height দিয়ে body-তে।
      
    URL → Network → HTML stream → DOM + CSSOM (+ JS) → Render tree → Layout → Paint → Composite → Pixels

    Browser process
    Address bar, tab, back/forward, permission। কোন tab কোন renderer পাবে ঠিক করে।
    
      
    Renderer process
    HTML/CSS parse, DOM, CSSOM, layout, paint। Chrome-এ Blink engine; প্রতিটা site আলাদা sandbox-এ।
    
      
    JavaScript engine
    Renderer-এর ভেতরে JS চালায় — Chrome-এ V8, Firefox-এ SpiderMonkey, Safari-তে JavaScriptCore। একই main thread-এ parsing আর JS, তাই JS চললে parsing থামে।
    
      
    Network process
    DNS, cache, HTTP, TLS, cookie। Download করা ডেটা renderer-কে stream করে দেয়।
    
      
    GPU process
    আঁকা layer-গুলো জুড়ে শেষ frame screen-এ দেয়; scroll আর animation মসৃণ রাখে।
    
      
    আরও থাকে
    Cache, cookie, localStorage, IndexedDB, Service Worker, extension আর security sandbox।
    
    
    
  
    

  
  
    
    
    ৬নোট: কোন script কখন চলে, কীসের অপেক্ষা করে
    
      
    Confusion দূর করার জন্য সব এক জায়গায়। প্রতিটা script চলার আগে কিছু জিনিস শেষ হওয়ার অপেক্ষা করে — কোনটা কীসের উপর নির্ভর করে, নিচে দেখুন।
    

    
    একটাই নিয়ম মনে রাখুন
      Script চলার মুহূর্তে browser যত CSS-এর কথা জানে আর যেগুলো তখনো নামছে, সেগুলো শেষ হওয়া পর্যন্ত অপেক্ষা করে — শুধু async বাদে। সাধারণ script আগে চলে, তাই শুধু উপরের CSS চেনে। defer/module HTML পড়া শেষে চলে, তাই নিচের CSS-সহ সব চেনে।
    

    
    
      
    <script src>কিছু না দিলে
    
        
    parser tag-এ পৌঁছায় (থামে)+download শেষ+উপরের CSS শেষ+আগের script শেষ→চলে→parser আবার পড়ে
    
      
    <script>…</script>inline
    
        
    parser tag-এ পৌঁছায় (থামে)+উপরের CSS শেষ→চলে→parser আবার পড়ে
    
      
    deferআর type="module"
    
        
    download শেষ+পুরো HTML পড়া শেষ+সব CSS শেষ (নিচেরটাও)+আগের defer শেষ→চলে→DOMContentLoaded
    
      
    asyncআর module async, JS দিয়ে বানানো script
    
        
    শুধু download শেষ→চলে·CSS, HTML পড়া, ক্রম — কিছুর অপেক্ষা নেই
    
    
    

    
    
      
    ScriptDownload-এর সময় parserDownloadCSSHTML পড়া শেষক্রমচলার সময় DOM-এ
    
      
        
    <script src>থামেঅপেক্ষা করেশুধু উপরেরনাঠিক থাকেশুধু উপরের অংশ
    
        
    inline <script>download নেই, থামে—শুধু উপরেরনাঠিক থাকেশুধু উপরের অংশ
    
        
    deferথামে নাঅপেক্ষা করেসবঅপেক্ষা করেলেখার ক্রমেপুরো DOM
    
        
    type="module"থামে নাঅপেক্ষা করেসবঅপেক্ষা করেলেখার ক্রমেপুরো DOM
    
        
    async / module asyncথামে না (চলার সময় থামে)অপেক্ষা করেনানাযেটা আগে নামেভাগ্যের উপর
    
          
    
    

    
    
      
    উদাহরণ: কে কোন CSS-এর জন্য অপেক্ষা করে
    
        
    <head>
  <link rel="stylesheet" href="a.css">
  <script defer src="app.js"></script>  <!-- a.css আর b.css দুটোর জন্যই -->
  <script src="old.js"></script>        <!-- শুধু a.css-এর জন্য -->
  <script async src="ga.js"></script>   <!-- কোনোটার জন্যই না -->
  <link rel="stylesheet" href="b.css">
</head>
    
        
    old.js-এ parser যখন থামে, তখনো b.css পড়াই হয়নি — browser জানেই না ওটা আছে। app.js চলে HTML পড়া শেষে, ততক্ষণে b.css-ও চেনা হয়ে গেছে।
    
      
    যেগুলো গুলিয়ে যায়
    
        
      
          
    • কিছু না দিলে = download শেষ এবং উপরের CSS শেষ — দুটোর মধ্যে যেটা পরে হয়, তখন চলে। পুরো সময় parser বন্ধ।
      • 
          
    • File আগে থেকে cache-এ থাকলেও সাধারণ script parser ওই লাইনে পৌঁছানোর আগে কখনো চলে না।
      • 
          
    • defer শুধু src থাকলে কাজ করে; inline <script defer>-এ কোনো প্রভাব নেই। কিন্তু inline type="module" defer-এর মতোই চলে।
      • 
          
    • type="module"-এ defer লেখা লাগে না; async দিলে async-এর নিয়মে চলে।
      • 
          
    • media="print"-এর মতো না-মেলা CSS কোনো script আটকায় না।
      • 
          
    • document.createElement("script") দিয়ে বানানো script নিজে থেকেই async।
      • 
          
    • async CSS-এর অপেক্ষা করে না, তাই offsetWidth বা getComputedStyle() পড়লে CSS আসার আগের ভুল মাপ পেতে পারে।
