1Array-এর নাম print করলে base address কী আসে?C

বেশিরভাগ expression-এ array-এর নাম নিজে থেকেই প্রথম element-এর pointer-এ রূপান্তরিত হয়ে যায়। একে array-to-pointer decay বলে। তাই ara আর &ara[0] একই address, অর্থাৎ array-র base address।

C 
int ara[5] = {10, 20, 30, 40, 50};

printf("%p\n", (void*)ara);      // base address, যেমন 0x7ffd1000
printf("%p\n", (void*)&ara[0]);  // একই address
printf("%p\n", (void*)(ara + 1)); // 0x7ffd1004 (int = 4 byte, তাই +4)

খেয়াল রাখার বিষয়

  • সরাসরি printf(ara) লিখলে ara-কে format string ধরা হয়, তাই এটা ভুল। address দেখতে চাইলে %p লাগবে।
  • sizeof(ara) আর &ara-তে decay হয় না। sizeof(ara) পুরো array-র size (এখানে 20 byte) দেয়। &ara-এর মান একই, কিন্তু type আলাদা: int (*)[5]।
  • Array আর pointer এক জিনিস নয়। Function-এ array পাঠালে সেটা pointer হয়ে যায়, তাই ভেতরে sizeof দিয়ে length পাওয়া যায় না।
2Extra data structure ছাড়া stack-এর middle element delete করোDSA

ধারণা: Recursion ব্যবহার করো। উপর থেকে element pop করে recursive call-এর ভেতর রেখে দাও (call stack সাময়িকভাবে জমা রাখে)। middle-এ পৌঁছে সেটা pop করে ফেলো। তারপর ফেরার পথে বাকিগুলো আবার push করো। কোনো extra array বা stack লাগে না।

C++ 
void deleteMid(stack<int>& s, int cur, int n) {
    if (cur == n / 2) {      // middle-এ পৌঁছেছি
        s.pop();             // এটাকেই delete করলাম
        return;
    }
    int x = s.top();
    s.pop();
    deleteMid(s, cur + 1, n);
    s.push(x);               // ফেরার পথে আগের element ফেরত
}

// ব্যবহার: deleteMid(s, 0, s.size());
// [1,2,3,4,5] → [1,2,4,5]
  • Time: O(n)। Space: O(n), কারণ recursion call stack ব্যবহার হয়।
  • Element সংখ্যা জোড় হলে "middle" দুটো থাকে। উপরের কোড উপর থেকে গুনে n/2-তম element মুছে। interviewer-কে জিজ্ঞেস করে নাও কোনটা চান।

4Recursive Fibonacci-এর time complexity কত?Complexity

প্রশ্নের কোড প্রতিবার fun(n-1) আর fun(n-2), দুটো call করে। তাই call tree প্রতি স্তরে প্রায় দ্বিগুণ হয়।

  • Time: O(2n)। সূক্ষ্মভাবে বললে Θ(φn), যেখানে φ ≈ 1.618।
  • Space: O(n), কারণ সবচেয়ে গভীর call chain-এর দৈর্ঘ্য n।

কীভাবে ভালো করা যায়

উপায়TimeSpace
Memoization (top-down DP)O(n)O(n)
Iterative (দুটি variable)O(n)O(1)
Matrix exponentiationO(log n)O(1)

এখানে অনেক subproblem বারবার হিসাব হয় (overlapping subproblems)। তাই cache করলেই জটিলতা exponential থেকে linear-এ নেমে আসে।

5SQL query-র execution order কী?SQL

আমরা যেভাবে লিখি আর database যেভাবে চালায়, দুটো আলাদা। চালানোর ক্রম:

  1. FROM আর JOIN (ON সহ)
  2. WHERE: row filter
  3. GROUP BY
  4. HAVING: group filter
  5. SELECT: column আর expression হিসাব, alias তৈরি
  6. DISTINCT
  7. ORDER BY
  8. LIMIT / OFFSET
SQL 
SELECT dept, COUNT(*) AS total   -- 5
FROM employees                   -- 1
WHERE salary > 30000             -- 2
GROUP BY dept                    -- 3
HAVING COUNT(*) > 5              -- 4
ORDER BY total DESC              -- 7
LIMIT 10;                        -- 8
কেন গুরুত্বপূর্ণ: SELECT-এর alias WHERE-এ ব্যবহার করা যায় না, কারণ WHERE আগে চলে। কিন্তু ORDER BY-তে করা যায়, কারণ সেটা পরে চলে। WHERE aggregate ফাংশন নিতে পারে না, সেখানে HAVING লাগে।
6অনেক column-এ redundant data থাকলে table কীভাবে optimize করবে?DBMS

উত্তর Normalization: data ভেঙে ছোট ছোট সম্পর্কযুক্ত table-এ ভাগ করা, যাতে একই তথ্য একবারই থাকে। এতে তিন ধরনের anomaly কমে: insert, update ও delete anomaly।

Normal formশর্ত
1NFপ্রতি cell-এ একটাই মান (atomic), কোনো repeating group নেই
2NF1NF + কোনো non-key column composite key-এর অংশবিশেষের উপর নির্ভর করে না
3NF2NF + কোনো non-key column আরেকটা non-key column-এর উপর নির্ভর করে না (transitive dependency নেই)
BCNFপ্রতিটি functional dependency-র বাঁ দিক একটি superkey

উদাহরণ: orders(order_id, customer_name, customer_phone, product)-এ একই customer-এর নাম ও ফোন প্রতিবার লেখা হয়। এটাকে customers(id, name, phone) আর orders(order_id, customer_id, product)-এ ভাগ করো।

Trade-off: বেশি normalize করলে query-তে বেশি JOIN লাগে। পড়ার চাপ বেশি হলে নির্দিষ্ট জায়গায় ইচ্ছা করে denormalize করা হয়।

7Java code-এ access modifier-এর violation কীভাবে খুঁজে বের করবে?Java
Modifierএকই classএকই packageঅন্য package-এর subclassঅন্য সবখান
privateহ্যাঁনানানা
default (কিছু না লিখলে)হ্যাঁহ্যাঁনানা

Java 
class Account {
    private double balance;            // শুধু Account-এর ভেতরে
    protected String owner;

class Test {
    void run() {
        Account a = new Account();
        a.balance = 500;               // ভুল: balance has private access in Account

সাধারণ violation আর সমাধান

  • অন্য class থেকে private field সরাসরি ধরা। সমাধান: public getter/setter দাও। এতে validation করার সুযোগও থাকে।
  • অন্য package-এর non-subclass থেকে protected বা default member ধরা।
  • Override করার সময় access কমানো যায় না। যেমন public method-কে protected করে override করলে compile error হয়।

Compiler error message-ই সাধারণত বলে দেয় কোন member, কোন class-এ private access। সেই লাইন থেকে খুঁজলেই হয়।

8OOP-এর মূল ধারণাগুলো বলোOOP
  • Encapsulation: data আর সেই data-র উপর কাজ করা method এক class-এ বেঁধে রাখা। field private রেখে getter/setter দিয়ে access দেওয়া হয়।
  • Abstraction: অপ্রয়োজনীয় ভেতরের বিবরণ লুকিয়ে শুধু দরকারি interface দেখানো। abstract class আর interface এর উদাহরণ। গাড়ি চালাতে ইঞ্জিন কীভাবে চলে জানা লাগে না।
  • Inheritance: একটি class আরেকটির বৈশিষ্ট্য পেয়ে code পুনর্ব্যবহার করে (Dog extends Animal)।
  • Polymorphism: একই নামের ক্রিয়া ভিন্ন আচরণ করে।
    • Compile-time: method overloading (একই নাম, আলাদা parameter)।
    • Runtime: method overriding (subclass parent-এর method নতুনভাবে লেখে)। কোন method চলবে তা object-এর আসল type দেখে ঠিক হয়।
Java 
abstract class Shape { abstract double area(); }

class Circle extends Shape {
    double r;
    Circle(double r) { this.r = r; }
    double area() { return Math.PI * r * r; }
}
class Square extends Shape {
    double s;
    Square(double s) { this.s = s; }
    double area() { return s * s; }
}

Shape x = new Circle(2);   // reference-এর type Shape, object-এর type Circle
x.area();                  // Circle-এর area() চলবে (runtime polymorphism)
অতিরিক্ত প্রশ্ন আসতে পারে: abstract class বনাম interface, overloading বনাম overriding, composition বনাম inheritance, SOLID principle।

10Table-এর duplicate row দেখানোর SQL লেখোSQL

ধরা যাক users(id, name, email)-এ email duplicate খুঁজছি।

SQL 
-- ১) কোন মান কতবার আছে
SELECT email, COUNT(*) AS times
FROM users
GROUP BY email
HAVING COUNT(*) > 1;

-- ২) duplicate row-গুলো পুরোটা দেখতে
SELECT *
FROM users
WHERE email IN (
    SELECT email FROM users GROUP BY email HAVING COUNT(*) > 1
)
ORDER BY email;

-- ৩) window function দিয়ে, প্রথমটা বাদ দিয়ে বাকিগুলো
SELECT * FROM (
    SELECT *, ROW_NUMBER() OVER (PARTITION BY email ORDER BY id) AS rn
    FROM users
) t
WHERE rn > 1;

11Queue দিয়ে stack বানানো যায়?DSA

হ্যাঁ যায়। Queue হলো FIFO, stack হলো LIFO। কৌশল হলো push করার পর পুরোনো সব element ঘুরিয়ে পেছনে পাঠানো, যাতে নতুনটা সামনে চলে আসে।

Python (একটি queue) 
from collections import deque

class MyStack:
    def __init__(self):
        self.q = deque()

    def push(self, x):
        self.q.append(x)
        for _ in range(len(self.q) - 1):     # পুরোনোগুলো ঘুরিয়ে পেছনে
            self.q.append(self.q.popleft())

    def pop(self):
        return self.q.popleft()              # সামনেই সবচেয়ে নতুন

    def top(self):
        return self.q[0]
  • Push O(n), pop/top O(1)।
  • দুই queue-র উপায়: push-এ নতুন element q2-তে রাখো, তারপর q1-এর সব q2-তে ঢালো, শেষে q1 আর q2 বদলাও। জটিলতা একই।
  • বিপরীত প্রশ্নও আসে: দুটি stack দিয়ে queue বানাও। এখানে amortized O(1) পাওয়া যায়।
12Chessboard-এ কিছু knight আছে। আর কিছু knight এমনভাবে বসাও যেন কেউ কাউকে attack না করেGraph

প্রশ্নটা অস্পষ্ট, তাই আগে clarify করো: board কত বড়, আগের knight-গুলো নিজেরা কি একে অপরকে attack করছে, আর "সর্বোচ্চ বসাতে হবে" নাকি "যেকোনো valid ভাবে বসালেই হবে"।

ধাপ ১: Attack-এর graph

প্রতিটি ঘর একটি node। Knight-এর 8টি L-আকৃতির চাল ধরে দুটি ঘরের মধ্যে edge। যে ঘর কোনো বসানো knight-এর edge-এ পড়ে সেটা attacked।

ধাপ ২: সহজ approach (যেকোনো valid placement)

attacked = সব বসানো knight-এর 8 চালের ঘর (BFS/DFS লাগে না, সরাসরি হিসাব)
for each ঘর (r, c):
    if ঘর খালি এবং attacked নয়:
        knight বসাও
        তার 8 চালের ঘর attacked চিহ্নিত করো

এটা greedy, তাই valid উত্তর দেয় কিন্তু সর্বোচ্চ সংখ্যা নাও দিতে পারে।

ধাপ ৩: সর্বোচ্চ সংখ্যা

  • Knight সবসময় উল্টো রঙের ঘরে যায়। তাই board-এর graph bipartite (সাদা ঘর একদিকে, কালো ঘর অন্যদিকে)।
  • এর মানে একই রঙের সব ঘরে knight বসালে কেউ কাউকে attack করে না। খালি n×n board-এ সর্বোচ্চ ⌈n²/2⌉টি (8×8-এ 32)।
  • আগের knight দুই রঙেই থাকলে সমস্যা হলো bipartite graph-এ maximum independent set। সেটা মোট ঘর − maximum matching (König's theorem), matching বের করতে Hopcroft–Karp ব্যবহার হয়। আগের knight-এর ঘর বাধ্যতামূলক ধরতে হবে।

15দুজন একই সময়ে একই ticket reserve করলে কী হবে? কীভাবে সমাধান করবে? কয়টি API লাগবে?Concurrency

সমস্যা: এটা race condition। দুটি request একসাথে "ticket খালি আছে" দেখে, দুজনেই reserve করে ফেলে। ফলে একটি ticket দুজনের নামে চলে যায় (double booking)।

সমাধান (ভালো থেকে সাধারণ ক্রমে)

  1. Atomic conditional update: check আর update একটি SQL statement-এ। কতটি row বদলাল তা দেখো। 
    UPDATE tickets
SET status = 'RESERVED', user_id = :uid
WHERE id = :ticket AND status = 'AVAILABLE';
-- affected rows = 1 হলে সফল, 0 হলে অন্য কেউ আগে নিয়েছে → 409 Conflict
  2. Pessimistic lock: transaction-এর ভেতরে SELECT ... FOR UPDATE। row-টা lock হয়, দ্বিতীয় request অপেক্ষা করে।
  3. Optimistic lock: version column রাখো। update-এ WHERE version = :old দাও, মিললে version+1। না মিললে retry বা reject।
  4. Unique constraint: UNIQUE(event_id, seat_no) দিলে database নিজেই দ্বিতীয় insert আটকে দেয়।
  5. Temporary hold: আগে 5-10 মিনিটের জন্য seat আটকে রাখো (expiry সহ), payment হলে confirm করো। না হলে auto-release। Redis lock বা TTL দিয়ে করা যায়।

16Password কীভাবে এমনভাবে নিরাপদ রাখবে যে admin-ও দেখতে না পারে? Hashing কীভাবে শক্ত করবে?Security

Password কখনো plain text-এ রাখা যাবে না। Encrypt করে রাখাও যথেষ্ট নয়, কারণ key যার কাছে আছে সে decrypt করতে পারে। দরকার one-way hash, যা থেকে মূল password ফেরত পাওয়া যায় না। Login-এর সময় দেওয়া password hash করে সংরক্ষিত hash-এর সাথে মেলানো হয়।

Hashing শক্ত করার উপায়

  • ধীর, adaptive algorithm: Argon2id, bcrypt বা scrypt। সরাসরি SHA-256 নয়, কারণ সেটা এত দ্রুত যে attacker সেকেন্ডে কোটি কোটি অনুমান করতে পারে।
  • Salt: প্রতিটি password-এর জন্য আলাদা, random মান। এতে দুজনের password এক হলেও hash আলাদা হয়, আর rainbow table কাজ করে না। Salt গোপন রাখতে হয় না, hash-এর সাথেই রাখা যায়।
  • Cost factor: কাজ কতটা ভারী হবে তা ঠিক করে। হার্ডওয়্যার দ্রুত হলে এটা বাড়ানো যায়।
  • Pepper (ঐচ্ছিক): সবার জন্য একটি গোপন মান, যা database-এর বাইরে (secret manager বা HSM) রাখা হয়।
Node.js (bcrypt) 
const bcrypt = require("bcrypt");

const hash = await bcrypt.hash(password, 12);      // salt নিজে তৈরি করে, cost = 12
const ok   = await bcrypt.compare(input, hash);    // login-এর সময় মেলানো

এর বাইরে

  • Password ভুলে গেলে "পুনরুদ্ধার" নয়, "reset link" দাও। কারণ hash থেকে ফেরত পাওয়া যায় না।
  • Rate limiting, account lockout, আর MFA যোগ করো।
  • Password hash কখনো log বা API response-এ পাঠিও না।
17Trigger কী? Cascading বলতে কী বোঝায়?DBMS

Trigger হলো এমন একটি stored procedure যা table-এ নির্দিষ্ট ঘটনা (INSERT, UPDATE, DELETE) ঘটলে database নিজে চালিয়ে দেয়। BEFORE বা AFTER দুই সময়েই বসানো যায়। সাধারণ ব্যবহার: audit log, data validation, derived value আপডেট।

MySQL 
CREATE TRIGGER log_salary_change
AFTER UPDATE ON employees
FOR EACH ROW
INSERT INTO salary_audit (emp_id, old_salary, new_salary, changed_at)
VALUES (OLD.id, OLD.salary, NEW.salary, NOW());

Cascading

Parent row বদলালে বা মুছলে তার সাথে সম্পর্কিত child row-এও স্বয়ংক্রিয়ভাবে সেই পরিবর্তন প্রয়োগ হওয়া। Foreign key-তে এটা লেখা যায়:

CREATE TABLE orders (
  id INT PRIMARY KEY,
  customer_id INT,
  FOREIGN KEY (customer_id) REFERENCES customers(id)
    ON DELETE CASCADE      -- customer মুছলে তার সব order-ও মুছবে
    ON UPDATE CASCADE      -- customer-এর id বদলালে order-এও বদলাবে
);
Optionকাজ
CASCADEপরিবর্তন child-এও প্রয়োগ
SET NULLchild-এর foreign key null হবে
RESTRICT / NO ACTIONchild থাকলে parent বদলাতে বা মুছতে দেবে না

"Cascading trigger" বলতে একটি trigger-এর কাজ আরেকটি trigger চালু করে দেওয়াকেও বোঝায়। এতে অপ্রত্যাশিত লুপ আর debug-এর সমস্যা হতে পারে, তাই বেশি ব্যবহার করা ঠিক না।

19Browser-এ কোনো website খুললে কী কী ঘটে? Content কীভাবে render হয়?Networking
  1. URL parse: protocol (https), domain, path আলাদা করা।
  2. DNS lookup: domain থেকে IP খোঁজা। প্রথমে browser cache, তারপর OS cache, router, শেষে resolver (যে প্রয়োজনে root → TLD → authoritative name server-এ যায়)।
  3. TCP connection: three-way handshake (SYN, SYN-ACK, ACK)। HTTP/3-এ QUIC (UDP) ব্যবহার হয়।
  4. TLS handshake: certificate যাচাই, key বিনিময়, এরপর যোগাযোগ এনক্রিপ্টেড।
  5. HTTP request: GET / HTTP/1.1 আর header (Host, Cookie, Accept...)।
  6. Server-এর কাজ: load balancer → web/app server → প্রয়োজনে database বা cache → response তৈরি।
  7. Response: status code (200, 301, 404...), header আর HTML body।
  8. Browser rendering:
    • HTML parse করে DOM তৈরি, CSS parse করে CSSOM।
    • দুটি মিলিয়ে render tree।
    • Layout: প্রতিটি element-এর মাপ আর অবস্থান।
    • Paint আর Composite: pixel আঁকা ও layer জোড়া।
    • CSS, JS, ছবির জন্য আলাদা request। <script> parsing আটকাতে পারে, তাই defer/async ব্যবহার হয়।

গতি বাড়ানোর উপায়: CDN, caching, compression (gzip/brotli), HTTP/2 multiplexing, keep-alive।

21Histogram-এ সবচেয়ে বড় আয়তক্ষেত্রের ক্ষেত্রফল (LeetCode 84)DSA

Subarray নিলে সবচেয়ে ছোট মানটি উচ্চতা, আর element সংখ্যা প্রস্থ। ক্ষেত্রফল সর্বোচ্চ করতে হবে। Brute force O(n²) বা O(n³)। ভালো সমাধান monotonic stack দিয়ে O(n)।

ধারণা: উচ্চতা বাড়তে থাকলে stack-এ রাখো। ছোট একটি bar এলে stack থেকে বড় bar-গুলো pop করো। প্রতিটি pop-করা bar সেই উচ্চতায় ডানে-বাঁয়ে যতদূর যেতে পারে সেটাই তার সম্ভাব্য আয়তক্ষেত্র।

Python 
def largest_rectangle(heights):
    stack = []                       # (শুরুর index, উচ্চতা)
    best = 0
    for i, h in enumerate(heights + [0]):   # শেষে 0 দিলে সব pop হয়ে যায়
        start = i
        while stack and stack[-1][1] > h:
            idx, height = stack.pop()
            best = max(best, height * (i - idx))
            start = idx              # নতুন bar এই bar-এর বাঁ সীমা পর্যন্ত প্রসারিত হবে
        stack.append((start, h))
    return best

print(largest_rectangle([2, 1, 5, 6, 2, 3]))   # 10  (5 আর 6 নিয়ে 5 × 2)
  • Time: O(n), প্রতিটি element একবার push আর একবার pop হয়।
  • Space: O(n)।

প্রথম marble 14তলা থেকে ফেলো। না ভাঙলে লাফ এক কমিয়ে (13, 12, 11 ...) পরের তলায় যাও। প্রথম marble-এর প্রতিটি অতিরিক্ত drop-এর বিনিময়ে দ্বিতীয়টির সম্ভাব্য ধাপ এক কমে। তাই যেখানেই প্রথমটি ভাঙুক, মোট drop-এর সংখ্যা worst case-এ সবসময় 14।

n + (n-1) + (n-2) + ... + 1 ≥ 100
n(n+1)/2 ≥ 100  →  n = 14      (14 × 15 / 2 = 105)

প্রথম marble-এর তলা: 14, 27, 39, 50, 60, 69, 77, 84, 90, 95, 99, 100

উদাহরণ: প্রথমটি 39তলায় ভাঙল (27-এ ভাঙেনি)। দ্বিতীয়টি দিয়ে 28 থেকে 38 পর্যন্ত একটি একটি করে যাও। সর্বোচ্চ ধাপ 11, আগে 3টি ফেলা হয়েছে, মোট 14।

SQL 
-- ১) subquery দিয়ে
SELECT *
FROM products
WHERE price IN (
    SELECT price FROM products GROUP BY price HAVING COUNT(*) > 1
)
ORDER BY price;

-- ২) self join দিয়ে (জোড়া আকারে)
SELECT a.product_name AS p1, b.product_name AS p2, a.price
FROM products a
JOIN products b
  ON a.price = b.price AND a.product_id < b.product_id;

-- ৩) window function দিয়ে
SELECT * FROM (
    SELECT *, COUNT(*) OVER (PARTITION BY price) AS same_price
    FROM products
) t
WHERE same_price > 1;

a.product_id < b.product_id দিলে নিজের সাথে নিজের জোড়া আর উল্টো জোড়া (A-B আর B-A) বাদ যায়। শুধু দাম আর সংখ্যা চাইলে GROUP BY price HAVING COUNT(*) > 1-ই যথেষ্ট।

25OOP-এ threading ব্যাখ্যা করোThread

Thread হলো একটি process-এর ভেতরের সবচেয়ে ছোট execution unit। একই process-এর thread-গুলো heap আর code share করে, কিন্তু প্রত্যেকের নিজস্ব stack আর register থাকে। Multithreading দিয়ে একসাথে একাধিক কাজ করা যায়, যেমন UI চালু রেখে ব্যাকগ্রাউন্ডে file download।

Java 
class Task implements Runnable {          // Runnable বেশি পছন্দনীয়: extends Thread-এ inheritance আটকে যায়
    public void run() {
        System.out.println("চলছে: " + Thread.currentThread().getName());
    }
}

public class Main {
    public static void main(String[] args) {
        new Thread(new Task(), "worker-1").start();   // start() নতুন thread বানায়, run() সরাসরি ডাকলে বানায় না

        // বাস্তবে ThreadPool ব্যবহার হয়
        ExecutorService pool = Executors.newFixedThreadPool(4);
        pool.submit(new Task());
        pool.shutdown();
    }
}

Shared data আর সমস্যা

class Counter {
    private int count = 0;
    public synchronized void increment() { count++; }   // একসাথে একটি thread ঢুকবে
}

count++ আসলে read, add, write এই তিন ধাপ। synchronized না থাকলে দুই thread একসাথে করলে একটি update হারিয়ে যায় (race condition)। Deadlock, starvation-ও থ্রেডিংয়ের পরিচিত সমস্যা।

  • Thread বনাম Process: thread হালকা আর memory share করে। Process-এর আলাদা address space।
  • Thread-এর life cycle: New → Runnable → Running → Blocked/Waiting → Terminated।
  • ColdFusion-এ <cfthread> ট্যাগ দিয়ে thread চালানো যায়।
26Database-এ কোনো পরিবর্তন হয়েছে কিনা কীভাবে বুঝবে?Database

প্রশ্নটা বিস্তৃত, তাই কী ধরনের পরিবর্তন (row, schema) আর কত দ্রুত জানতে হবে সেটা জিজ্ঞেস করে নাও। প্রচলিত উপায়:

  1. Timestamp/version column: প্রতিটি table-এ updated_at বা version রাখো। নিয়মিত WHERE updated_at > :last_check query করো (polling)। সহজ, কিন্তু delete ধরা যায় না। তখন soft delete লাগে।
  2. Trigger + audit table: প্রতিটি পরিবর্তনের আগের ও পরের মান আলাদা table-এ লেখা।
  3. Checksum/hash: table বা row-এর hash আগেরটির সাথে তুলনা করা (যেমন MySQL-এ CHECKSUM TABLE)।
  4. Change Data Capture (CDC): database-এর transaction log (MySQL binlog, PostgreSQL WAL) পড়ে পরিবর্তন stream করা। Debezium এর জনপ্রিয় tool। real-time চাইলে সবচেয়ে ভালো।
  5. Database-এর নিজস্ব সুবিধা: PostgreSQL-এর LISTEN/NOTIFY, SQL Server-এর Change Tracking।
  6. Application স্তরে: ORM hook বা event, যেখানে সব write এক জায়গা দিয়ে যায়।

27ColdFusion কী আর কেন ব্যবহার করা হয়?ColdFusion

ColdFusion একটি server-side web application platform। এর ভাষা CFML (ColdFusion Markup Language), যাতে HTML-এর মতো tag দিয়েও লেখা যায়, আবার cfscript দিয়ে JavaScript-এর মতো করেও। দুটি প্রধান engine: Adobe ColdFusion (বাণিজ্যিক) আর Lucee (open source)। এটি JVM-এর উপর চলে এবং code Java bytecode-এ compile হয়, তাই Java library সরাসরি ব্যবহার করা যায়।

CFML 
<cfquery name="users" datasource="mydb">
    SELECT id, name FROM users WHERE active = <cfqueryparam value="1" cfsqltype="cf_sql_integer">
</cfquery>

<cfoutput query="users">
    #users.name#<br>
</cfoutput>

কেন ব্যবহার হয়

  • দ্রুত development: database query (cfquery), email (cfmail), file (cffile), PDF, REST API, scheduled task, caching সবই built-in।
  • Java integration: JVM-এ চলে, তাই বিদ্যমান Java ecosystem কাজে লাগে।
  • Legacy ও enterprise application: বহু প্রতিষ্ঠানের চালু বড় system ColdFusion-এ লেখা, আর তা ধরে রাখা ও বাড়ানোর কাজ চলতে থাকে।
  • নিরাপত্তা সুবিধা: cfqueryparam দিয়ে SQL injection ঠেকানো সহজ।
Interview-এর আগে ColdFusion-এর মূল ধারণা (tag, cfquery, cfoutput, cfscript, component/.cfc) একটু দেখে যাও। Candidate-এর ব্লগ অনুযায়ী প্রথমেই এ নিয়ে প্রশ্ন এসেছিল। এই পদের জন্য আগের অভিজ্ঞতা লাগবে এমন নয়, তবে মৌলিক ধারণা বলতে পারলে ভালো লাগে।
28HR: কেন WellDev? ভবিষ্যৎ পরিকল্পনা কী? তোমার সবচেয়ে বড় শক্তি কী?HR

এই প্রশ্নগুলোর "সঠিক" উত্তর নেই, তবে ভালো উত্তরের একটা কাঠামো আছে। উত্তরে নিজের সত্যিকারের কথা বলো, মুখস্থ বুলি নয়।

১) কেন WellDev?

  • আগে কোম্পানির ওয়েবসাইট, কাজের ধরন আর ব্যবহৃত technology দেখে যাও। সত্যিকারের একটি-দুটি কারণ বলো (শেখার সুযোগ, কাজের ধরন, কাজের পরিবেশ)।
  • নিজের আগ্রহের সাথে মেলাও: "আমি ... নিয়ে কাজ করতে চাই, আর আপনাদের ... project/technology সেটার সাথে মেলে।"
  • কোম্পানি সম্পর্কে অনুমানে কিছু বোলো না, যা জানো না তা এড়িয়ে যাও।

২) ভবিষ্যৎ পরিকল্পনা

  • স্বল্পমেয়াদে: প্রথম 1-2 বছরে মৌলিক দক্ষতা শক্ত করা, code quality আর team-এর কাজের ধারা শেখা।
  • দীর্ঘমেয়াদে: একজন নির্ভরযোগ্য, দায়িত্ব নিতে পারা engineer হওয়া, ধীরে ধীরে বড় feature বা design-এর দায়িত্ব নেওয়া।
  • কোম্পানির সাথে বেড়ে ওঠার কথা বলো। "বিদেশে চলে যাব" ধরনের কথা এড়াও।

৩) শক্তি

  • একটি-দুটি শক্তি বেছে নাও আর ছোট উদাহরণ দাও। যেমন: "আমি সমস্যা ভেঙে ছোট অংশে সমাধান করি। আমার একটি project-এ ... bug খুঁজতে এভাবে ...।"
  • দুর্বলতা জিজ্ঞেস করলে সত্যি বলো আর তা কাটাতে কী করছ তা বলো।
